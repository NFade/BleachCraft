## 0. Что есть сейчас (факты из кода)

- **Правая рука приклеена к рукояти.** `FirstPersonHand.gripOffset` делает кулак неподвижной точкой модели меча (`FIST_X/Y/Z`, `cm`). `held.arm` в `pose_override` сдвигает хват ВДОЛЬ меча, а не руку относительно меча. Свободной правой руки нет.
- **Меч в руке задаётся одним сдвигом.** `HeldPose.Values`: `lift` (вектор), `arm` (вектор), `roll_stow`, `roll_held`. Поворота меча в хвате нет (кроме `bc_item` для третьего лица, `BcItemPose`).
- **Левая рука только как рука ножен.** `ScabbardRenderer.renderFirstPerson` рисует её через `renderVanillaArmAt(!left)`, и только пока `DrawRig.sayaOut(prog) < 1`. После доставания ножны и левая рука уходят (ранний `return`). Значит в BASE, SHIKAI и BANKAI наш код левую руку в первом лице не рисует. Что добавит сама ванила: UNVERIFIED.
- **Геометрия руки.** `renderVanillaArm` двигает ванильную модель руки матрицей, плечо задано константами (`translate(f*-1.0, 3.6, 3.5)`). Поворот в hand frame идёт вокруг точки кисти, не плеча, поэтому вынос руки вперёд требует компенсации плеча (см. N1). Кулак ванильный и без пальцев: указательный палец и раскрытая ладонь не передаются, передаются положение и наклон руки.
- **Камера.** Есть FOV kick через `ScreenFx.shunpoRush` (`GameRendererMixin.getFov`, только при `changingFov`), `reduceMotion` и `photosensitiveSafe` уже учитываются. Наклона и крена камеры нет.
- **Третье лицо.** BC-поза у наших мечей пустая (`design/results/bc5.md`, решение 1), руки ванильные. Наших PA-слоёв нет: `playerAnim` в `mod/src` встречается только в `BcItemPose` и `BcFirstPersonModeMixin`. Поза каста в третьем лице будет новым слоем.
- **Каст.** `ClientNet.castAbility` / `castKido` шлют C2S, сервер отвечает `EffectEventS2C` с `effectId`. Кидо уже есть в `KidoId`: `BYAKURAI`, `SHAKKAHO`, `SAI`.
- **Вывод.** Сейчас анимируются только доставание и ножны. Ни одна абилка не даст жест без новых механизмов ниже.

## 1. Новые механизмы (общие для абилок)

- **N1. Свободная левая рука, первое лицо.** Левая рука получает собственную позу по ключам, не привязанную к ножнам. Нужна, когда ножны ушли (т.е. в обнажённых состояниях, где ножны и так не рисуются). Реализация: `renderVanillaArm(left=true)` с матрицей позы и компенсацией плеча. Сложность: средняя.
- **N2. Свободная правая рука (рука отпускает меч).** Нужна Бякуе в банкае (рука пуста) и кидо без меча. Сейчас `gripOffset` жёстко привязывает кулак к мечу, поэтому для N2 надо режим «рука ведёт ключи, меч отдельно/на земле». Сложность: средняя-большая.
- **N3. Поворот меча в хвате (дельта вокруг рукояти).** Меч и кулак поворачиваются вместе: дельту применить до `lift`-push, а вектор кулака повернуть той же матрицей, иначе рука отстанет. Нужна для Hakuteiken, Tsukishiro, Mae, Absolute zero, удара BC. Сложность: средняя.
- **N4. Таймлайн жестов (driver).** Один класс: ключи (t, поза), easing (`io`, `oe`, `ios`, `lin`, по образцу VFX), старт по `EffectEventS2C` (для всех игроков) или по запросу клиента (себе, с упреждением), прерывание при выходе из состояния. Источник данных: `pose_override.json` (dev) и ресурс (prod). Сложность: средняя. Основа всего остального.
- **N5. Камера по таймлайну.** Дельты pitch, yaw, roll, FOV. Путь: как у `ScreenFx` (FOV kick) плюс миксин на камеру. Учитывать `reduceMotion` и `photosensitiveSafe` (VFX 2.0). Сложность: малая-средняя.
- **N6. Третье лицо: PA-слой «reiatsu_ability».** Каналы `rightArm`, `leftArm`, `body` (наклон корпуса 2-5 градусов). **`rightItem` в слой не класть:** `BcItemPose` включается, когда любой PA-слой двигает `rightItem` (bc5, решение 3), и наш слой получил бы чужую коррекцию Rx(-55). Конфликт с BC-ударом: каст блокирует удары BC (флаг в `BcAttackGate`), а не конкурирует слоями. Это решение за агентом BC5, его файлы не трогаем. Сложность: средняя-большая.
- **N7. Пустая рука без предмета, первое лицо.** `FirstPersonHand` рисует руку только для `ZanpakutoItem`. Для кидо без меча и банкая Бякуи нужен хук на пустой стек в `HeldItemRenderer` (новый миксин, не трогать миксины BC5). Сложность: средняя.

## 2. Соглашения для таймлайна

- Каналы: **R** правая рука, **L** левая рука, **S** меч, **C** камера.
- Все значения это **дельты от покоя** удерживаемой позы (`held.arm`, `held.lift`). Так подстройка held тянет за собой все жесты.
- Координаты hand frame, блоки (1 блок = 16 px). **x** вправо в абсолютной системе (левая рука наружу = отрицательный x), **y** вверх, **z** вперёд = отрицательный (как `FIST_Z = -0.316` в `FirstPersonHand`). Зеркалирование для левой руки делает код (`mx`), поэтому числа в этом документе абсолютные.
- **S**: lift (блоки) и поворот вокруг рукояти (градусы, rx, ry, rz). Знак rx (кончик вверх или вниз) проверяется по превью; здесь rx < 0 = кончик вверх (UNVERIFIED).
- Строки: `R/L: [t, x, y, z, roll]` (roll = поворот предплечья, градусы); `S: [t, lx, ly, lz, rx, ry, rz]`; `C: [t, pitch, yaw, roll, fov]`.
- **t** в секундах от старта жеста. «VFX t=…» указывает момент эффекта из VFX_STORYBOARD. Для себя поза стартует по запросу с упреждением `lead` = 0.15 с (компенсация RTT), для других игроков по `EffectEventS2C`. Если EffectEvent пришёл позже, таймлайн сдвигается без скачка позы.
- Пример записи в `pose_override.json` (dev, ключ новый):
  ```
  "cast": {
    "byakuya.bankai.scatter": {
      "L": [[0.00, 0.10, -0.05, -0.25, 0], [0.30, -0.25, 0.00, -0.30, 0]],
      "R": [[0.00, -0.10, -0.05, -0.25, 0]],
      "S": [],
      "C": [[2.50, -3, 0, 0, 0]]
    }
  }
  ```
  Ключи в примере условные, значения проверяются в превью.

## 3. Дыхание (idle) и общий принцип

- **Idle:** синус 0.22 Гц. R: y ±0.004. S: lift y ±0.003. Roll ±0.8 градуса. L (если свободна): y ±0.01, фаза +90 градусов. Во время жеста idle умножается на (1 − вес жеста), переход плавный. При `reduceMotion` амплитуда ×0.5.
- **Принцип:** руки никогда не замирают ровно. Даже в удержании есть дыхание (1-2 мм за 4 с).
- **Жест:** антиципация 0.1-0.2 с (противоход), удар, удержание 0.3-0.8 с, возврат 0.3-0.5 с. Два больших жеста подряд без возврата не идут.
- **Одна рука ведёт, вторая поддерживает.** Две активные большие руки одновременно только в финальных сценах (Scatter, Bankai release).
- **Лимит:** кулак без пальцев, знаки и «указания пальцем» передаются через направление руки.

## 5. Третье лицо: общие правила

- PA-слой `reiatsu_ability`: `rightArm`, `leftArm`, `body`. `rightItem` в слой не класть (см. N6).
- Каст блокирует удары BC: флаг в `BcAttackGate` (решает агент BC5). Конкуренции слоёв не делаем.
- Удалённые игроки видят жест по `EffectEventS2C` (caster и effectId), отдельный пакет не нужен.
- Дальше 32 блоков третье лицо можно упростить (только руки, без корпуса), вблизи полный клип.

## 9. Риски

- `rightItem` в PA: `BcItemPose` сработает на наш слой (N6).
- Клиппинг руки и меча о верх экрана при rx около -150 (Rukia release, Chire).
- Смена модели на рукоять (Chire): точка кулака задана по геометрии модели, проверить.
- Пальцы не передаются: кидо и «указание» держатся на направлении руки.
- Рассинхрон позы и EffectEvent из-за RTT: компенсируется `lead` 0.15 с, проверить в игре.
- Производительность: таймлайн дешёвый (десятки float на кадр). PA-слоям дальних игроков нужен LOD.
- Заморозка позы в Absolute zero и Hakuteiken должна совпадать с серверным HITSTOP, иначе жест «поплывёт».
