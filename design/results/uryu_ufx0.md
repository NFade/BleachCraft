## 2. U-FX 0 scaffolding

### Textures (`tools/gen_uryu_textures.py`, `python -I`, Pillow + numpy, deterministic: two runs give identical hashes)
Helpers copied verbatim from `gen_fx_textures.py` (not imported, so the committed PNGs cannot drift when the other generator changes); `fx_glow.png` is not touched. Outputs (all committed): `textures/fx/uryu_glow.png` + `uryu_glow_atlas.json` (512 x 256 RGB, 23 sprites plus the reserved block `spare`), `textures/particle/reishi_mote_0..3.png` + `particles/reishi_mote.json`, `flechette_0..2.png` + `particles/flechette.json`, `textures/fx/pentagon_scar.png` (128), `burst_scar.png` (64), `uryu_glitter.png` (64, tileable). NOT generated (after the Blender agent): `uryu_vein_skin.png`, `item/uryu_fx_diffuse.png`, `uryu_fx_emissive.png`. `--sheet X` writes a contact sheet.

Deviations from the recipes (judgement calls, all visible in the generator): `lens` uses circles of radius 78 centred at +-50 px (the spec's 52 / 40 gives a 24 x 66 px lens in a 64 x 128 cell); `beam_glitter` base is faded to zero at the top and bottom edge (a flat 0.35 floor would draw a box); `crescent` is a frown (centre below) with the apex at y 8 so it fits 32 px; `chain` is three interlocking ovals (period 21.3 px, tileable); every round sprite has a radial window so its border is black (checked by a test). The storyboard says "24 Quincy sprites": there are 23 plus `spare`.

### Atlas 2 in code
- `core/fx/GlowAtlasTable.java` (new, pure): rect tables of BOTH atlases, `consistent()` (no overlap, in bounds). `GlowAtlasTableTest` fails when the Java table, `URYU_RECTS` of the generator, `GLOW_RECTS` of `gen_fx_textures.py`, the written `*_atlas.json` or the PNG sizes disagree, when a sprite region of the PNG is empty, when `spare` is not black, and when a round sprite has a lit cell border.
- `GlowSprite.java`: constructor `(atlas, name)`, fields `atlas`, `x,y,w,h`, UVs per atlas size, `ofAtlas(int)`. **Names for the next agents (enum constant = upper case of the sprite name):** `ZEICHEN_STAR, WEB_WHEEL, BURST_RAYS, CRESCENT, PLATFORM_DISC, SPARK_CLUSTER, ZEICHEN_CROSS, PENT_LINE, CHEVRONS, DIAMOND_STAR, FLAKE, NEEDLE, VEIN_TRACE, GLITTER, DASH, DASH_B, CHAIN, LENS, FLECHETTE_TRAIL, BEAM_GLITTER, RUNE_BAND, STAR_FIELD, FENCE` (atlas 1; `spare` has no constant). The 17 old sprites keep their names. `Phase6Fx` now asks `GlowSprite.ofAtlas(0)` so the phase 6 atlas grid is unchanged.
- `FxGlowBatch.java`: `ATLAS_U`, layer `reiatsu_glow_u` (`layerU()`, same program, linear filter, additive, no depth write), a second `BufferBuilder` with its own `BufferAllocator`, created on the first atlas 1 sprite of the frame (`bufU()`, lines 605-624), used by the pool loop (line 834) and by `Emitter.quad` (line 526); drawn after the atlas 0 buffer (line 857); one extra draw call only when needed. `uryu.glow` multiplies the colour of atlas 1 sprites (lines 527 and 713). A stale open buffer from a failed frame is closed at the start of the next (line 635).
- `FxShapes.java:376-400`: a shape whose `cell` is an atlas 1 sprite (strips with `beam_glitter`, `fence`, `rune_band`, `flechette_trail`) goes to its own buffer and `layerU()`. Needed so the next agents can use Quincy cells on `Q:strip/beam/wall` without touching FxShapes again.
