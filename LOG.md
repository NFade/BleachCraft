Rules learned:
- (a) FIRST person needs ry=180 and THIRD person ry=0 (the two hand frames differ by a flip about Y) to get spine up and edge down in both. - (b) Left-hand JSON entries must EQUAL the right-hand ones: `Transformation#apply(leftHanded)` already mirrors rotation y/z and translation x (verified in source and screenshots 02, 03c).
- (c) Fixed: the object centre is 0.21 m above the grip, so the translation recentres it in the frame.

### Step B fix: third person sori direction (reusable rule for Byakuya)
Bug: on the armor stand the blade curved the wrong way (tip bent away from the body, edge toward the body). Fix: thirdperson_right/left rotation [45, 0, 0] -> **[45, 180, 0]**, translation and scale unchanged, left entries equal right (rule b). Rule: `Transformation` applies rotation as extrinsic Z, then Y, then X (`Quaternionf#rotationXYZ`), so `ry` acts BEFORE `rx` and, while the blade is still along model +Y, `ry = 180` is a roll of 180 degrees about the blade axis. It swaps edge and spine (and the flats) without moving tip or grip, so the tip stays up and the grip stays in the hand; the later `rx = 45` then tilts the blade up-forward. Result (`r6` set, stand from both sides and front, sealed and shikai, both hands): tip up, the curve bows so that the tip bends back toward the stand's body, the edge faces away/forward; the shikai ribbon hangs from the pommel behind the hand. First person is unchanged (its ry = 220 already contains the other flat). Ground, fixed and gui were not affected by the bug and not changed. For a future model whose sori goes the wrong way in one view, flip it by adding 180 to that view's `ry` (first/third person use different frames, so the two views need their own value).
