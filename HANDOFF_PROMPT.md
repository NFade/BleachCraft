## 3. Оркестрация и правила

- Работай как оркестратор: код и Blender делегируй субагентам (`Agent`, `model: "sonnet"` для реализации, `haiku` для механики), сам принимай результат по скриншотам и тестам. Opus (`model: "opus"`): использовано 5 из 6 (Gate A, ADR, Gate B, Gate C, дизайн эффектов). **Остался один вызов, зарезервирован под Gate D.** Не трать его раньше.
- Параллельные кодовые агенты работают в отдельных git worktree (`git worktree add .claude/worktrees/<name> -b <branch>`; параметр `isolation: "worktree"` не работает, если сессия не в git-репозитории). Blender: один агент за раз. Модели в Blender уже готовы, правки моделей только по необходимости.
- Субагенты отвечают не более 200 слов, результат кладут в файлы и `LOG.md`. Лимит сессии может оборвать агента (HTTP 429): возобнови его через `SendMessage` (имя или id).
- Не делай: `generate_3d` без разрешения; push без просьбы; правку `.mcp.json` (он под чужую машину); рип ассетов и копирование текста вики; объявлять что-то невозможным, пока не изолирована причина (меняй по одной переменной).
- `core/` без импортов Minecraft (`CorePurityTest`). Каждый шаг: `gradlew build test`, `runPhase4` и `runPhase5` зелёные, скриншоты, раздел в `LOG.md` с числами и списком UNVERIFIED, локальный коммит по шагу. Все имена API Yarn 1.21.1 проверяй по декомпилированным исходникам (`mod/.gradle/loom-cache/.../*-sources.jar`), без угадывания.
- Коммит-трейлер: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
